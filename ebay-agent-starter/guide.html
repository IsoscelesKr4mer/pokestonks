What this is

A starter kit, not a finished program. You put one file into an empty folder and open Claude Code there. It interviews you, then builds the agent with you, one phase at a time, stopping after each so you can look at what it did.

What you end up with: a folder you dump card photos into, an agent you can talk to from your phone, and eBay listings that get drafted on demand and published only when you say so.

It is written for the way you already sell. Nothing here assumes you switch categories or change how you source — it automates the part between having the cards and having them listed.

You do not need to know how to code. You do need to read what the agent proposes and say no when it looks wrong. That part is not optional — it is the part that keeps it accurate.

Before you start

  • A computer you can leave running, if you want to drive it from your phone. Mac, Windows or Linux.
  • Claude Code — the terminal version of Claude. Same model you already use, with access to your files and the ability to run commands. Install this first.
  • An eBay seller account in reasonable standing.
  • An eBay developer account — free, and separate from your seller account, at developer.ebay.com. Sign up now; approval is not instant.
  • Node.js and Python. The agent will tell you if something is missing.
  • A Discord account, only if you want the phone control.

Budget about two hours for the first pass. Most of that is waiting on eBay's developer console, not on you.

Setup

  1. Make an empty folder.

    $ mkdir ebay-agent
$ cd ebay-agent

  2. Put CLAUDE.md in it. That is the only file you need to begin.

  3. Open Claude Code in that folder.

    $ claude

  4. Say this:

    Read CLAUDE.md and start the setup.

  5. Answer its questions and follow along. It stops after every phase. Read what it built. If an assumption looks wrong, say so — fixing it in phase one is far cheaper than after it has created ninety listings.

Three things worth knowing

It asks before it publishes

That is deliberate, and you should keep it. The agent drafts the listing, shows you the title, the price and why it picked that price, and waits. Everything else can be automatic. That one step should not be.

Identifying the card is the hard part

Listing is a solved API call. Knowing that the card in the photo is number 344 and not 345 is where the actual work lives, and it is why the very first question is what you sell. Sports cards need the manufacturer's checklist; Pokémon has TCGCSV; Magic has Scryfall; a niche game may have a community database or nothing at all. If there is no source for your category, say so on day one — the build changes shape, and that is fine.

It will be wrong sometimes, and you are the check

It reads small print off photographs and quotes prices from public data. Both of those fail. The version of this that works is the one where you glance at a draft and push back. Nearly every expensive mistake in the build this came from was caught by the seller saying that doesn't look right — and being correct.

What will bite you

None of these are hypothetical. Each one cost real money or a public correction in the build this guide came from.

  1. A declared weight is not a measured weightShipping declarations get padded on purpose when the buyer pays. Read one back later as a product spec and your own padding becomes a fact. Weigh things.
  2. Round shipping up only when the buyer paysWhen you buy the label, declare the true weight. Carriers bill to the next whole pound anyway, so padding buys nothing and can push you over a boundary.
  3. eBay caches listing photos by URLRe-upload a corrected image to the same path and the old one stays live forever, while every API call reports success. Host it under a new filename.
  4. Verify before you create, and again after you publisheBay's verify call runs full validation and creates nothing. After publishing, read the listing back — a create response is not proof that buyers see what you intended.
  5. Look at every image before it goes upA crop that quietly ate the product, or a spec label photographed upside down, passes every automated check there is.
  6. Normalising an identifier can merge two different itemsStrip the punctuation out of a code and a special parallel can collapse into its plain counterpart — one SKU, one photo filename, two different cards, and no error message.
  7. Test bulk operations on one item firstEditing thirty live listings on an untested assumption is how you discover the API refuses your listing type.
  8. Never invent a product detailNot a promo name, not a contents count, not a barcode. If the box does not say it and you cannot verify it, leave it out. A GTIN field is allowed to be empty. It is not allowed to be wrong.

If you get stuck

Tell the agent what happened and paste the exact error. It has eBay's error codes and the common failure modes in its instructions, and eBay's messages are usually precise about what is missing even when they read like nonsense.

And if it is genuinely stuck, ask Michael — he has hit most of this already.
