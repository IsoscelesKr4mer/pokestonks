# Plan: eBay sales sync (manual trigger)

User-triggered "Sync from eBay" button on `/sales` that pulls new orders from eBay Fulfillment API, presents them in a batch preview modal with per-row edits, and creates sale entries on confirm.

## Decisions (from brainstorming)

- **Preview UX:** batch confirm with per-row edit. One modal, all new orders, "Confirm All" or edit/skip per row.
- **Backfill:** none. First sync's `since` watermark = the moment of OAuth connection. Historical 15 sales stay manually-logged.
- **Environment:** production directly. Sync is read-only on the eBay side; confirm step gates all pokestonks writes.

## DB schema (Drizzle migration)

```sql
CREATE TABLE ebay_credentials (
  user_id uuid PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  refresh_token text NOT NULL,
  access_token text,
  access_token_expires_at timestamptz,
  ebay_user_id text,        -- eBay's seller username (for display)
  created_at timestamptz DEFAULT now() NOT NULL,
  updated_at timestamptz DEFAULT now() NOT NULL
);

CREATE TABLE ebay_listing_mappings (
  id bigserial PRIMARY KEY,
  user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  ebay_item_id text NOT NULL,
  mappings jsonb NOT NULL,  -- [{catalog_item_id: bigint, qty: int}, ...]
  created_at timestamptz DEFAULT now() NOT NULL,
  updated_at timestamptz DEFAULT now() NOT NULL,
  UNIQUE(user_id, ebay_item_id)
);

CREATE TABLE ebay_synced_orders (
  id bigserial PRIMARY KEY,
  user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  ebay_order_id text NOT NULL,
  sale_group_id uuid REFERENCES,  -- nullable: null if skipped
  synced_at timestamptz DEFAULT now() NOT NULL,
  skipped boolean DEFAULT false NOT NULL,
  UNIQUE(user_id, ebay_order_id)
);

CREATE TABLE ebay_sync_state (
  user_id uuid PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  last_synced_at timestamptz,
  created_at timestamptz DEFAULT now() NOT NULL
);
```

RLS policies: each table scoped to `user_id = auth.uid()`.

## Service layer: `lib/services/ebay.ts`

- `refreshAccessToken(userId)` → exchange refresh token for new access token, update `ebay_credentials`
- `getOrders(userId, since)` → call Fulfillment API, return parsed Order objects
- `proposeSaleFromOrder(order, mappings, catalogItems)` → returns either a `BundleSaleInput` shape or a "needs mapping" prompt object

## API endpoints

- `GET /api/ebay/auth/init` → redirect to eBay authorize URL with state + scopes (sell.fulfillment)
- `GET /api/ebay/auth/callback` → exchange auth code, store refresh token + access token, redirect to /sales
- `POST /api/ebay/sync-preview` → fetch new orders since last_synced_at, return `{ proposals: [...], unmapped: [...] }`
- `POST /api/ebay/sync-confirm` → accept array of confirmed proposals, create bundle sales, mark ebay_synced_orders. Also accept any new mappings the user defined inline.
- `GET /api/ebay/mappings` → list existing mappings
- `POST /api/ebay/marketplace-account-deletion` → eBay-required webhook endpoint (responds to deletion notifications + verification challenge)

## UI

- `/sales` page header: "Sync from eBay" button. If no credentials: shows "Connect eBay" instead, links to /api/ebay/auth/init.
- `SyncPreviewDialog` component: lists new orders. Each row shows:
  - eBay order ID
  - Sale date
  - Item title (from eBay)
  - Proposed pokestonks items + qty + revenue/fees split
  - Per-row: "Edit mapping" (opens inline mapping wizard) or "Skip" toggle
- `EbayListingMappingWizard` inline component: shown when a row has no mapping. Lets user pick 1+ catalog items + qty.

## OAuth flow details

eBay uses Authorization Code grant with a "RuName" (registered redirect URL identifier, not the URL itself). Flow:

1. `/api/ebay/auth/init` → redirect to `https://auth.ebay.com/oauth2/authorize?client_id=APP_ID&response_type=code&redirect_uri=RUNAME&scope=https://api.ebay.com/oauth/api_scope/sell.fulfillment&state=<csrf-token>`
2. User accepts on eBay site → redirected to `EBAY_REDIRECT_URI?code=<authcode>&state=<csrf>`
3. Callback: POST to `https://api.ebay.com/identity/v1/oauth2/token` with `grant_type=authorization_code`, `code=<authcode>`, `redirect_uri=RUNAME`. Returns `access_token` (2hr expiry) + `refresh_token` (18mo expiry).
4. Store both in `ebay_credentials`. Set `access_token_expires_at = now() + 2hr`.

Access token refresh:
- Before each API call, check `access_token_expires_at`. If within 5min of expiry, refresh.
- Refresh: POST to token endpoint with `grant_type=refresh_token`, `refresh_token=<stored>`, `scope=<same scopes>`. Returns new access token (refresh token unchanged).

## Required eBay compliance: Marketplace Account Deletion notifications

eBay requires production apps to handle account deletion webhooks. Implementation:
- `POST /api/ebay/marketplace-account-deletion` 
- GET request: respond with verification challenge (sha256 of challenge_code + verification_token + endpoint URL)
- POST request: payload of deleted user → soft-delete any of their data in our DB
- Single-user app: just verification challenge matters; deletion case is no-op since we don't store eBay user data beyond OAuth tokens
- Configure URL + verification_token in eBay developer portal under "Alerts & Notifications"
